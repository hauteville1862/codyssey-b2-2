## 3. PR 작성 규칙 — 담당 이나현
<!-- SEC3:START -->
- 제목은 커밋 컨벤션과 같은 형식: `<type>: <무엇을>`
- 본문 필수 항목: 연결 이슈(`Closes #번호`), 변경 사항(What), 변경 이유(Why), 테스트/검증(How)
- 하나의 PR 에는 하나의 목적만 담는다. 리뷰어가 30분 안에 읽을 수 있는 크기로 쪼갠다.
<!-- SEC3:END -->

## 4. 코드 리뷰 규칙 — 담당 이나현
<!-- SEC4:START -->
- "LGTM" 이나 이모지만 남기는 리뷰는 인정하지 않는다. 파일·줄을 근거로 질문, 대안, 위험, 개선 중 하나 이상을 적는다.
- 좋은 예: `mean([]) 이면 ZeroDivisionError 가 납니다. ValueError 로 막으면 어떨까요?`
- 작성자는 모든 코멘트에 반영 커밋 해시를 적어 답하거나, 반영하지 않는 이유를 답한다.
- 반영을 확인한 리뷰어가 Approve 한다. 승인 1명 이상이어야 병합할 수 있다.
<!-- SEC4:END -->
