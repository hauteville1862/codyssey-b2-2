# Contributing Guide

팀 협업 규칙이다. 각 절은 담당자가 자기 PR 에서 채운다.

## 1. 브랜치 전략(GitHub Flow) — 담당 임유현
<!-- SEC1:START -->
- `main`: 항상 동작하는 상태. 직접 push 금지(Branch Protection), PR 과 승인 1명으로만 병합한다.
- `feature/*`: 작업 하나당 브랜치 하나. main 에서 만들고 PR 병합 뒤 삭제한다.
- 작업 흐름: 이슈 생성 → 브랜치 → 커밋 → push → PR(`Closes #이슈`) → 리뷰·반영 → 승인 → 병합
- 우리 팀이 GitHub Flow 를 고른 이유(3줄)
  1. main 하나만 지키면 되어 3인 팀에 규칙이 단순하다.
  2. 모든 변경이 PR 리뷰를 거쳐 기록이 남는다.
  3. 릴리스 주기가 없어 develop·release 브랜치가 필요 없다.
<!-- SEC1:END -->

## 2. 브랜치 네이밍과 커밋 메시지 컨벤션 — 담당 임유현
<!-- SEC2:START -->
- 브랜치: `feature/<이니셜>-<작업>` (소문자, 하이픈). 예: `feature/a-text-utils`
- 이슈가 있으면 이니셜 앞에 번호를 붙여도 된다. 예: `feature/12-a-login` (PR·이슈를 브랜치 이름으로 찾기 쉽다)
- 커밋: `<type>: <무엇을 했는지>`. type 은 `feat`, `fix`, `docs`, `refactor`, `test`, `chore`
- 제목은 50자 안팎, 명령형, 끝에 마침표 없음. 무엇을 바꿨는지 대상이 드러나야 한다.
- 금지(의미 없는 메시지): `update`, `fix`, `temp`, `wip`, `final`, `bug fix`, `edit file`
<!-- SEC2:END -->

## 3. PR 작성 규칙 — 담당 이나현
<!-- SEC3:START -->
- 제목은 커밋 컨벤션과 같은 형식: `<type>: <무엇을>`
- 본문 필수 항목: 연결 이슈(`Closes #번호`), 변경 사항(What), 변경 이유(Why), 테스트/검증(How)
- 하나의 PR 에는 하나의 목적만 담는다. 리뷰어가 30분 안에 읽을 수 있는 크기로 쪼갠다.
<!-- SEC3:END -->

## 4. 코드 리뷰 규칙 — 담당 이나현
<!-- SEC4:START -->
- "LGTM" 이나 이모지만 남기는 리뷰는 인정하지 않는다. 파일·줄을 근거로 질문, 대안, 위험, 개선 중 하나 이상을 적는다.
- 좋은 예: `mean([]) 이면 ZeroDivisionError 가 납니다. ValueError 로 막으면 어떨까요?`
- 작성자는 모든 코멘트에 반영 커밋 해시를 적어 답하거나, 반영하지 않는 이유를 답한다.
- 반영을 확인한 리뷰어가 Approve 한다. 승인 1명 이상이어야 병합할 수 있다.
- 리뷰 요청을 받으면 24시간 안에 첫 응답을 남긴다. 늦어지면 PR 코멘트로 예정 시간을 알린다.
<!-- SEC4:END -->

## 5. 충돌 발생 시 대응 흐름 — 담당 박경내
<!-- SEC5:START -->
1. **발견**: `git merge origin/main` 또는 PR 화면에서 충돌을 확인한 사람이 PR 코멘트로 알린다.
2. **최신화**: 자기 브랜치에서 `git fetch origin` → `git merge origin/main` (공유 브랜치는 rebase 하지 않는다).
3. **판단**: 충돌 구간의 양쪽 의도를 읽고 keep both / choose one / refactor 중 고른다. 판단이 어렵다면 상대 작성자와 코멘트로 합의한다.
4. **검증**: 충돌 표식(`<<<<<<<`, `=======`, `>>>>>>>`)이 남지 않았는지 확인하고 실행·doctest 를 다시 돌린다.
5. **기록**: 해결 커밋 뒤 `docs/conflict-resolution.md` 에 상황·표식·해결 과정·결과·배운 점을 남긴다.
6. **재요청**: 원래 리뷰어에게 리뷰를 다시 요청한다. 해결 커밋에서 무엇을 골랐는지 PR 코멘트로 요약한다.
<!-- SEC5:END -->

## 6. 병합 전 공통 체크리스트
<!-- CHECKLIST:START -->
- [ ] 리뷰어 1명 이상의 승인을 받았다
- [ ] 리뷰 코멘트에 모두 답하거나 반영했다
<!-- CHECKLIST:END -->
